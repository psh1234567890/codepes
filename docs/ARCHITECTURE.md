# 아키텍처

## 목표

CodePes는 별도 계정이나 데이터베이스 없이도 빠르게 열리고, 데이터 제공처에 일시적인 문제가 있어도 검색과 일정 내보내기를 계속 사용할 수 있도록 설계되었습니다.

## 구성

```text
국내외 공식 API·페이지 ─┐
                       ├─ scripts/sync-contests.mjs
수동 검증 JSON ────────┘          │
                              ▼
             competitions.generated.json
                    │                   │
             빌드 번들 fallback     GitHub main Raw
                    │                   │
                    └───────┬───────────┘
                            ▼
                 런타임 검증·최신 시각 비교
                            │
                            ▼
                     React 브라우저 앱
              ┌─────────────┼──────────────┐
              ▼             ▼              ▼
          검색·필터      localStorage      ICS·공유·이슈
```

## 프런트엔드

- React 19과 TypeScript로 UI와 상태를 구성합니다.
- Vite가 개발 서버와 프로덕션 번들을 담당합니다.
- 검색, 필터, 정렬은 현재 브라우저 메모리에서 실행합니다.
- 선택한 대회 ID는 URL의 `contest` 쿼리에 반영해 공유할 수 있습니다.
- 관심 대회 ID는 `codepes-bookmarks` 키로 `localStorage`에 저장합니다.
- 캘린더 파일은 브라우저에서 RFC 5545 형식의 `.ics` 문자열을 생성해 다운로드합니다.
- 제보 폼은 자체 서버로 전송하지 않고 미리 채운 GitHub 이슈 작성 URL을 엽니다.

## 데이터 계층

### 빌드 시점

`scripts/sync-contests.mjs`가 공식 API와 수동 검증 데이터를 정규화, 검증, 중복 제거한 뒤 `src/data/competitions.generated.json`을 만듭니다. 생성 데이터는 앱 번들에 포함되어 항상 사용할 수 있는 fallback이 됩니다.

### 실행 시점

앱은 GitHub Raw의 `main` 브랜치에서 동일한 JSON을 가져옵니다. `src/lib/competition-data.ts`가 각 필드와 날짜, URL, 열거형 값을 검사하고 번들보다 오래되지 않은 데이터만 선택합니다. 요청은 제한 시간 안에 끝나지 않거나 검증에 실패하면 번들 데이터로 복구됩니다.

### 자동 갱신

GitHub Actions 동기화 워크플로는 6시간마다 또는 수동 실행으로 다음 작업을 수행합니다.

1. 잠금 파일 기반 의존성 설치
2. 대회 데이터 동기화
3. 프로덕션 빌드 검증
4. 생성 JSON이 실제로 바뀐 경우에만 커밋과 push

정적 앱을 매번 다시 배포하지 않아도 브라우저가 최신 Raw JSON을 읽을 수 있습니다. 새 UI 코드나 번들 fallback을 갱신할 때는 프로덕션 재배포가 필요합니다.

## 배포

Vite의 Cloudflare 플러그인이 정적 애셋과 Worker를 빌드합니다. `worker/index.ts`는 애셋을 제공하고 HTML의 사이트 원점 표시를 실제 배포 원점으로 치환합니다. 프로덕션 사이트는 Sites 프로젝트로 배포합니다.

공개 저장소와 Sites 배포는 서로 다른 배포 대상입니다.

- GitHub: 소스, 이슈, Pull Request, 정기 데이터 JSON
- Sites: 사용자가 접속하는 웹 애플리케이션

## 신뢰 경계

- 외부 JSON은 신뢰하지 않고 런타임 검증 후 사용합니다.
- 공식 링크를 열면 사용자는 CodePes 경계를 벗어나 제3자 서비스로 이동합니다.
- GitHub 이슈는 공개될 수 있으므로 민감정보를 넣지 않습니다.
- 브라우저 저장소는 계정 동기화나 백업을 제공하지 않습니다.
- CodePes는 대회 접수 성공, 자격 판단, 일정 변경을 보증하지 않습니다.

## 테스트와 검증

`npm run verify`가 다음 단계를 순서대로 실행합니다.

1. TypeScript 타입 검사
2. Vitest 단위 테스트
3. 프로덕션 빌드

데이터 정규화, 중복 제거, 런타임 데이터 검증, 검색·필터, 캘린더 생성처럼 사용자 결과에 직접 영향을 주는 로직을 우선 테스트합니다.

## 의도적으로 없는 기능

현재 다음 구성은 없습니다.

- 자체 API 서버와 데이터베이스
- 회원가입, 로그인, 클라우드 동기화
- 이메일 알림
- 사용자 행동 분석 또는 광고 추적

이 기능을 추가하려면 개인정보 처리, 보안, 운영 비용, 데이터 이전 계획을 먼저 문서화해야 합니다.
