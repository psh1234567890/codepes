# 로드맵

이 문서는 방향을 공유하기 위한 계획이며 일정이나 구현을 보장하지 않습니다. 실제 우선순위는 공개 이슈와 사용자 피드백을 바탕으로 조정합니다.

## 현재 기반

- 대회 검색, 필터, 정렬, 상세 보기
- 브라우저 기반 관심 대회 저장과 저장 목록 보기
- 전체·저장·개별 `.ics` 일정 내보내기
- 공유 가능한 대회 선택 URL
- GitHub 이슈 기반 대회 제보와 정정 요청
- Codeforces 공식 API 자동 수집
- AtCoder 공식 예정 대회와 CodeChef 공식 JSON 자동 수집
- Devpost 공개 해커톤 목록·일정 자동 수집
- CTFtime 보안 CTF와 itch.io 게임잼 자동 수집
- DACON·DAKER 공식 페이지 수동 검증
- 원격 GitHub JSON 검증과 번들 fallback
- 타입 검사, 단위 테스트, 프로덕션 빌드 검증
- 오픈소스 라이선스와 운영 문서
- 공개 GitHub 저장소, CI, 이슈·Pull Request 템플릿
- 공개 Sites 배포와 README 라이브 링크
- 검색·필터·저장·공유·제보의 프로덕션 브라우저 검증
- 모바일 메뉴와 390px 화면의 가로 넘침 회귀 점검

## 1단계: 공개 운영 기반

- 정기 데이터 동기화와 충돌하지 않는 기본 브랜치 보호 방식 확정
- `v0.1.0` 태그와 릴리스 노트 발행
- 접근성 및 모바일 회귀 점검을 반복 가능한 체크리스트로 정리

## 2단계: 데이터 신뢰도

- 인증 가능한 Kaggle 공식 API와 추가 국내외 출처 조사
- 수동 데이터의 오래됨을 알리는 검토 기한과 상태 표시
- 동기화 실행 결과와 실패 원인을 사람이 확인하기 쉬운 형태로 기록
- 일정 변경과 취소 이력 표시
- 대회 ID와 중복 판정 규칙에 대한 회귀 테스트 확대

## 3단계: 사용자 가치

- 달력 애플리케이션별 가져오기 안내
- 저장 목록의 가져오기·내보내기
- 쿼리 문자열을 통한 검색·필터 공유
- 한국어와 영어의 최소 다국어 지원 가능성 검토
- 사용자가 동의한 범위에서만 운영 지표를 수집하는 방안 검토

## 4단계: 커뮤니티

- 첫 기여자를 위한 `good first issue` 정리
- 데이터 검증자와 코드 기여자의 역할 문서화
- 정기 릴리스와 변경 기록 운영
- 사용 사례, 교육 현장, 동아리의 피드백 공개 정리
- 버스 팩터를 낮출 공동 유지관리자 기준 마련

## 하지 않을 일

- 공식 출처 없이 일정을 추측해 자동 게시
- 사용자 동의 없는 이메일 수집이나 행동 추적
- 대회 참가 자격 또는 접수 성공을 CodePes가 보증하는 기능
- 보안·개인정보 계획 없는 성급한 계정 시스템 도입
